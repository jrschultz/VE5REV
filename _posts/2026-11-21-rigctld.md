All of digital ham radio is composed of the same 3 core components:

## 😈 rigctld
Lets a computer read and change settings on a radio transceiver over a cable or USB connection. ```rigctld``` (Hamlib daemon): Acts as a shared CAT (Computer Aided Transceiver) control server over TCP (commonly 127.0.0.1:4532), letting programs query or set frequency and mode without serial-port contention.

## 📟 Software Modem
Turns your message data into audio waveforms for the radio's audio input/output, handles modulation/demodulation and error correction/retransmissions, and exposes a local TCP interface. There are many examples of software modems now: VARA, xara, Mercury HF, etc.

## 📬 Interfacing Client
Gives you the user interface (web UI or CLI) to compose/read messages, picks the gateway or peer station, coordinates the session through the modem's TCP port, and often handles frequency/mode changes via ```rigctld.``` A well known example of this is [pat](https://getpat.io/). 
 
⚠️ **NOTE:** The modem & interfacing client can change, but the critical thing is ```rigctld``` It is built right in to all-in-one stand alone programs like WSJT-X. Because rigctld sits at the bottom as a network server, you can leave it running continuously and point ```pat JS8Call WSJT-X``` and ```fldigi``` at the same ```127.0.0.1:4532``` socket—switching modes without reconfiguring serial ports or fighting over COM/ /dev/ttyUSB* locks. 

# 📥 rigctld INSTALLATION

The open-source project ```hamlib``` is where all the magic happens. ```rigctld``` is part of ```hamlib```

You can install it from the terminal with:

```bash
sudo apt install libhamlib-utils
```

⚠️ **NOTE:** depending on your distribution, this might be different. This is for [Linux Mint](https://linuxmint.com/download.php). You can search with your package manager for ```hamlib``` and see what comes up.

# ⚙️ rigctld CONFIG

We need to tell ```rigctld``` what to do with this rather beastly terminal command. It looks crazy but I've broken it down for you with an explanation:

```bash
rigctld -m 3085 -r /dev/ttyACM0 -s 38400 -T 127.0.0.1 -t 4532 &
```

🟣 ```-m``` specifies the model. 3085 is the Icom IC-705. You can search for your rig with ```rigctld -l | grep FT-891```. Grep will search the list for the radio you specify, in this example it's the Yaesu FT-891 with a model number of 1036.
```1036  Yaesu	FT-891	20230328.7 Stable RIG_MODEL_FT891```

🟣 ```-r``` specifies the place where your radio is connected to your computer system. To find this, disconnect the radio's USB cord from the computer. In terminal use the following commmands: ```dmesg -c``` to clear the log. Then run ```dmesg | grep -E "ttyUSB|ttyACM"``` This will show you where your radio is connected, in our case /dev/ttyACM0

⚠️ **NOTE:** the IC-705 actually has two connection points, but we want the first one with ```0``` at the end.

🟣 ```-s``` specifies the baud or the serial speed. The IC-705 will auto adjust to whatever you specify. I use 38400, but other have good luck with 9600. 

🟣 ```-T``` and ```-t``` specify the listening address port. ```-T 127.0.0.1``` is the loop back for the computer itself. We want ```rigctld``` to listen there on port 4532 which is the default

🟣 ```&``` this final ```&``` tells ```rigctld``` to run in the background.

# 🦾 AUTOMATION

You can make an alias to the ```rigctld``` command in your ```.bashrc``` or ```.zshrc``` so you can easily start it up.

```bash
alias rig="rigctld -m 3085 -r /dev/ttyACM0 -s 38400 -T 127.0.0.1 -t 4532 &"
```

Simply ```source .zsrhc``` to load the alias. Then you simply type ```rig``` in the terminal to load it up.
